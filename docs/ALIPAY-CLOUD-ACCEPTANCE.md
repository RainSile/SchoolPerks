## 付款方式与验证边界

业务系统默认提供 `alipay.trade.page.pay` 官方网页收银台入口，已实际打开并确认金额和沙箱主机。账号密码方式因收银台安全组件网络／脚本错误停在提交过程，**未将这种方式记为通过**。

本次真实付款采用私有验收夹具：通过项目现有官方 SDK 从应用服务器调用 `alipay.trade.precreate`，使用同一业务订单号、金额及 HTTPS 通知地址生成付款码，再由用户在沙箱钱包付款。它验证供应商 → 部署通知入口 → 签名与业务校验 → 支付状态 → 正常退款链路；**不表示前端已增加预下单扫码支付模式**，也不表示网页账号密码方式已修复。未增加临时调试支付接口。

此前用户报告二维码立即失效，最终澄清实际使用普通支付宝扫码；换成沙箱版后付款成功。二维码解码与接口原文一致，订单到期时间和服务器时间也已核对，不能靠不断刷新二维码替代客户端环境核对。

供应商接口曾返回临时 HTTP 404；预下单夹具按同一订单号有限重试，业务退款 worker 按既有持久化任务规则处理。未改 Maven 依赖版本，未绕过客户端安全组件。

## 部署配置与留存

云端私有配置启用 `ALIPAY_SANDBOX_ENABLED=true`，本机加密配置继续保持关闭，避免本机测试订单通知到云端库。真实应用／商家标识、密钥、买家登录和支付密码不提交 Git。

`LOGGING_LEVEL_SDK=OFF` 关闭 SDK 原始签名报文日志，应用自身保留经过处理的状态与错误记录。公开文档不包含账号、完整订单号、付款链接、原始通知或数据库导出。更换服务器方法见[云端部署说明](CLOUD-DEPLOYMENT.md)。
