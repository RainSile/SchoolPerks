## 验收口径

七个开发阶段的核心代码已实现，不等于所有功能完成验收。智能助手、会话、模型、Embedding、Pinecone、AI 营销暂不测试；不调用模型或向量服务。短信供应商、MinIO、支付宝真实沙箱的缺失必须记为受阻，不能用 Mock 通过替代真实服务通过。

每条业务链分别检查：页面入口及状态 → 请求方法/参数/重复提交 → 登录和实时 RBAC → 资源所有权 → 正常/异常/边界/状态迁移 → MySQL 持久化与事务 → 幂等/有限并发 → Outbox/通知/审计 → 页面反馈及刷新后状态。没有证据的格子保持待测，返回 200 不足以证明全部通过。

证据分级：S=源码清点；U=单元/本地协议夹具；D=真实 MySQL + MockMvc，供应商端口可能为替身；F=浏览器 + HTTP/WebSocket 夹具；E=浏览器/真实 HTTP + 实际后端 + MySQL；X=真实外部服务。F、D 互相不能替代，D/F 也不能冒充 E 或 X。

状态：待测 / 进行中 / 已验证（注明层级）/ 失败 / 环境受阻 / 按约定排除。接口目录、实际执行轨迹、断言、报告共同作为依据，不以历史测试或源码阅读冒充本次实测。

## 每条用例记录格式

`编号 / 业务链 / 接口与角色 / 前置数据 / 操作 / 预期 HTTP 与业务码 / SQL 不变量 / 事件与页面预期 / 正常、异常、边界、越权、重复、有限并发维度 / 实际结果 / 证据层级与文件 / 对应缺陷`。

逐接口目录和调用轨迹用于识别覆盖缺口；仅被匿名 401 或参数 400 命中的接口不能标为完整业务通过。跨模块端口替身、后台任务直接调用、真实 HTTP、浏览器夹具分别标记。所有分支穷尽是需要持续补充的目标，不以测试条数或接口命中率声称已穷尽。
