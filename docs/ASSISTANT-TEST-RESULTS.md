# 智能助手业务与安全验收

日期：2026-10-26。范围：真实模型调用业务 API、多步写操作、管理员跨端授权、用户会话隔离、真实 SSE 与安全 Markdown。测试不部署常驻服务，不操作既有演示业务数据。

## 已验证结果

- 真实模型通过四条连续业务链：商家创建优惠草稿→提交审核→复核待审；平台管理员审核通过→跨端调用商家发布接口→复核公开状态；学生领取→查询券包；同一学生会话查询套餐→下单→取消→复核取消及库存恢复。
- 使用真实模型 API、实际 Spring HTTP/鉴权/领域服务、MySQL、Redis 和 MongoDB。模型生成的文字不作为成功依据，逐项断言优惠、审核、领取、订单和库存状态；未调用真实支付或文件上传供应商。
- 真实服务验收采用独立账号、学校、门店、优惠及套餐。每轮按根 ID 与外键关联清理，MongoDB 仅删除本轮 owner 的记录；最终 56 张表的行数和逐行摘要均一致。
- 最终完整回归：178 项 Boot 用例与 10 项集成适配器单元测试，共 188 项通过，失败/错误/跳过均为0；其中助手专项17项。真实模型四条链路另由一个显式外部集成用例验证，不将重复执行次数当成新增覆盖。
- 两组浏览器脚本通过：原有三端登录/RBAC/助手持久入口回归，以及真实延迟分片 SSE/中文 UTF-8 跨片、完成前展示增量、Markdown 表格/代码/安全链接、HTML/XSS 与远程图片阻断、停止后不自动重发、切换账号隔离、会话失效清除、手机尺寸检查。

## 权限检查

助手会话同时绑定实际 userId 和所属端；读取历史、查询消息状态、JSON 提问及 SSE 提问均验证归属。其他学生和具有跨端权限的管理员访问他人会话仍返回 404。

学生不能调用商家/管理工具；商家不能调用学生/管理工具，操作其他门店受到真实业务 API 拒绝。受限管理员保留细分权限。具有显式 `business:manage` 的 ADMIN 可以使用全部业务目录，保留 ADMIN 身份和审计 actor，不创建虚假门店成员、不伪造学生身份。动态的商家查看/分析能力也由领域能力目录显式汇总。

完整目录见 [ASSISTANT-BUSINESS-APIS.md](ASSISTANT-BUSINESS-APIS.md)。按 HTTP 方法区分相同路径的读取与修改；未分类的新端点默认不向模型开放。目录整表角色过滤、未知 operationId、URL 注入、写操作未获允许、同键不同消息/允许标记均有拒绝断言。

## 写操作和中断

每条消息默认只读，用户明确允许后执行其要求的业务写入。目录只提供固定接口，网关拒绝额外 path/query/body 字段，实际 API 继续执行 DTO、权限、版本、状态、库存和资源归属校验。

完成消息重放不重复调用模型。模型中断后的同键重试、同一轮重复工具调用不重复创建数据。MySQL 日志记录写尝试及脱敏结果；结果不确定时拒绝盲目重放和继续写入。长结果保留真实资源 ID 并返回有界摘要，重放复用同一摘要。业务成功后停止输出不表示撤销事务。

SSE 使用 SDK 的上游增量回调，通过队列在保留当前安全上下文的工作线程发送。有限线程池与队列限制并发；客户端断开会取消处理。每个增量及每次工具调用重新检查有效会话，JWT 到期或授权撤销后停止后续输出，未完成回答不保存为完成历史。原 JSON 接口保留。

## 缺陷与适用范围

本轮问题及处理见 [ASSISTANT-TEST-BUGS.md](ASSISTANT-TEST-BUGS.md)。没有遇到供应商余额不足；生产调用预算仍可配置，测试临时提高专属账号预算，不修改其他账号额度。

151 个目录接口的角色过滤不等于每个接口都由真实模型逐项执行过。真实模型验证以上四条业务链；其他接口依赖实际目录、固定网关、安全集成断言和原业务领域回归。真实短信、MinIO、支付宝支付/退款，以及所有参数组合和并发交错，不能因此宣称已完成最终验收。
