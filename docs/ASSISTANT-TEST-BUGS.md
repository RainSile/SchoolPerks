# 智能助手测试问题记录

业务阶段既有问题仍见 BUSINESS-TEST-BUGS.md。本文件仅记录本轮助手测试确认的问题，外部资源未配置不计为代码缺陷。

## AI-001：助手生成的幂等键超过订单 API 上限

- 发现：真实模型成功完成商家创建送审、管理员审核发布、学生领取后，在下单时收到 400。真实订单服务拒绝超过 64 位的 Idempotency-Key。
- 原因：工具网关将 `assistant_` 与完整 SHA-256 十六进制串直接连接，超过接口的长度上限。
- 范围：要求最多 64 位幂等键的业务写接口；没有创建订单或错误扣库存。
- 本轮处理：属于用户明确授权补齐的多步写操作范围，统一收敛到接口上限以内，保留 turn 与操作序号产生的稳定键；继续保留 MySQL 写操作结果日志。
- 状态：已修复并验证。真实模型下单→取消→查询已通过，订单为 CANCELLED，套餐库存恢复原值；前后数据库摘要一致。

## AI-002：平台能力汇总遗漏动态商家分析权限（已修复）

目录整表权限测试发现拥有 business:manage 的管理员缺少由门店成员动态贡献的 merchant:read/merchant:analytics:read，两个看板入口未出现在其可用目录。领域 PermissionContributor 现显式提供平台能力清单，仅对真实 ADMIN 且具有 business:manage 的账号汇总；普通账号的成员范围不扩大。完整目录与受限管理员回归通过。

## AI-003：长写结果在首次返回与重放时上下文不一致（已修复）

原工具结果超过上下文上限时，首次返回过大提示且不保留资源 ID，重放却读取完整结果。现先形成保留 ID/状态/版本的有界摘要，再保存日志，首次与重放一致。真实创建 6000 字符草稿→模型中断→同键重试的确定性 HTTP 集成测试通过，仅一份草稿。

## AI-004：同路径不同方法的端归属未区分（已修复）

目录复核发现 GET/PATCH /merchants/{id} 被共同归为学生端。实际业务鉴权仍拒绝学生修改门店，但商家助手无法发现正确资料修改工具。现 GET 属于学生公开查询、PATCH 属于商家业务；增加方法级断言，且未分类新增端点默认拒绝。

## AI-005：业务成功后工具轮数用尽导致没有最终总结（已修复并验证）

第二轮真实模型复测中，管理员已完成审核、发布、状态查询及发布记录查询，数据库确认为 PUBLISHED，但 10 个工具轮次后没有最终无工具回答，接口误报 ASSISTANT_NO_ANSWER。现将可配置上限提高至16个受限工具轮，在轮数用完时额外保留一次无工具总结，仅基于真实返回说明已完成和未完成内容；总工具调用上限和重试保护不变。最终真实模型四链、无工具总结专项及完整回归已通过。

管理员可选判断和跨端会话二次校验的问题已统一记录并修复，见 BUSINESS-TEST-BUGS.md 的 BIZ-001/BIZ-002。
